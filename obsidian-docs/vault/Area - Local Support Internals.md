## 1. What this app is

The Local Support App is Vectant's **local-side enforcement point** for human support sessions.
A user selects one workspace folder; the app pairs that workspace with one cloud support session;
and from then on **every byte that leaves the machine is classified, scanned, approved, hashed,
and hash-chained-audited locally** before release. The cloud can *request*; only the local app
*decides*.

Two crates:

| Crate | Path | Role |
|---|---|---|
| `vectant-local-support-app` | `Cargo.toml` (lib + test-daemon bin) | Security core: policy engine, scanner, pairing crypto, loopback HTTP API, preview gateway, Full Access broker, audit store |
| `vectant-local-support-desktop` | `desktop/Cargo.toml` | Tauri 2 shell: renderer IPC allowlist, native dialogs, pairing/relay clients, poll loops |

Trust model (from `docs/VECTANT_LOCAL_SUPPORT_APP_PLAN.md`): *"Automatic where safe, visible always,
permissioned when sensitive."* The security plan's non-negotiables shape nearly every module: no
hidden background access, no remote shell, no port scanning, no generic proxy, no cookie bridge,
no permanent grants.

### Version constants (`src/lib.rs:L20-L22`)

- `APP_PROTOCOL_VERSION = "local-support-mvp.1"` — echoed in every request envelope and verified on both sides.
- `POLICY_VERSION = "2026.07.05"` — receipts bind to this; mismatch ⇒ denial (`policy_version_mismatch`, `src/http.rs:L2502`).
- `SCANNER_VERSION = "scanner-2026.07.05"` — recorded in every scan report, response, receipt, and audit export.

`src/lib.rs` itself is only 22 lines: 17 `pub mod` declarations plus those constants. Every other
module hangs off this root.

## 3. Core primitives

### `src/policy.rs` (101 lines) — classification vocabulary

- `enum Classification { L0..L5 }` (L4-L11): the L0–L5 risk ladder used across the app. `L2`
  = clean text, `L4` = secrets detected / blocked-by-pattern, `L5` = hard-denied (workspace mismatch,
  path escape, denied approvals, scanner-unavailable fallback).
- `enum DecisionKind { Allow, Deny, ApprovalRequired, RedactThenApproval }` (L13-L19) — the four
  outcomes any capability check can produce. `RedactThenApproval` encodes "scrub locally, then still
  require a human".
- `RequiredApproval { scope: ApprovalScope(Once|Session), message }` (L22-L31); in practice only
  `Once` scope is constructed.
- `PolicyDecision` (L34-L41) carries decision + machine-readable `reason` + `classification` +
  optional approval + `redaction_required` + `log_user_visible`. Constructors `deny()` (L44),
  `allow()` (L55), `approval()` (L66), `redact_then_approval()` (L84) all force
  `log_user_visible: true` — denials are always surfaced to the user, never silent.

### `src/scanner.rs` (137 lines) — local secret scanning & redaction

- `SecretFinding { kind, start, end }` and `ScanReport { classification, findings, scanner_version }`
  (L6-L18). Classification rule (L99-L103): no findings ⇒ `L2`; any finding ⇒ `L4`.
- `ScannerError::Unavailable` (L20-L23) — a scanner that cannot run is a hard failure, not a pass.
- Pattern set (L34-L60), 10 regexes: `github_token` (`gh[pousr]_…`), `openai_api_key` (`sk-…`),
  `aws_access_key` (`AKIA…16`), `jwt` (`eyJ…` three segments), `private_key` PEM header,
  `database_url` (postgres/mysql/mongodb/redis URIs), `authorization_header`, `cookie`,
  `npm_token`, `firebase_service_account` JSON marker.
- `try_scan()` fails closed when unavailable (L80-L85); `scan()` sorts findings by offset (L98);
  `redact()` splices `[REDACTED:<kind>]` over each span, skipping overlaps (L111-L130).
- The scanner instance threads through audit, workspace, mutation, command output, and desktop-state
  scrubbing — one implementation, everywhere.

### `src/ipc.rs` (116 lines) — renderer→daemon command gate

- `IpcRequest { command, request_id, session_id }` / `IpcDecision { decision, reason, user_visible }`
  (L4-L15).
- `ALLOWED_IPC_COMMANDS` (L17-L44): exactly 26 commands — session.status/pause/resume/disconnect,
  pairing.start/confirm, workspace.pick/inventory, approval.file.review/approve/deny,
  approval.port.review/open/revoke, approval.revoke_session, full_access.pause/revoke/enroll,
  mutation.review/revert, process.visibility.pause/review, history.export/delete, update.check/install.
  Anything else is denied.
- `DANGEROUS_COMMAND_FRAGMENTS` (L46-L69): substrings that deny even if they'd somehow match the
  allowlist — exec, shell, command, write, delete/remove, readfile, openpath, keychain, clipboard,
  screen, accessibility, token, bearer, device_private, private_key, credential, secret, local_log,
  audit_raw. This is the "renderer can never ask about secrets" invariant, tested in
  `tests/security.rs` (`desktop_ipc_blocks_renderer_secret_and_device_key_access`).
- `decide_ipc_request()` (L71-L98): identifiers validated by `is_safe_ipc_identifier` (≤128 chars,
  `[A-Za-z0-9_.:-]`, no leading/trailing space) then command normalized (lowercase, ≤80 chars,
  charset-restricted) before allowlist lookup. Denial reasons: `invalid_schema`,
  `dangerous_ipc_command_blocked`, `ipc_command_not_allowed`.

### `src/lifecycle.rs` (84 lines) — teardown guarantees

- `PendingApprovalQueue` (L5-L29): trivial ID list tracking outstanding approvals during cleanup.
- `LifecycleCleanupReport` (L32-L41): eight booleans asserting the end state — cloud/local tokens
  revoked, preview tokens revoked, agent tokens revoked, streams stopped, pending approvals cleared,
  session disconnected, **`hidden_daemon_running: false`** (the anti-"hidden background agent" promise,
  tested by `uninstall_cleanup_leaves_no_hidden_daemon_state`).
- `disconnect_cleanup()` (L58-L70): disconnect session → drop per-session port approvals → clear
  preview traffic guard → clear pending approvals → report `complete()`.
- `uninstall_cleanup()` (L72-L84) currently delegates to disconnect cleanup.

## 4. Identity & pairing

### `src/pair.rs` (772 lines) — ed25519 device identity, DPAPI at-rest, challenge proofs

Structures:
- `PairingCode { code, fingerprint, expires_in_seconds }` (L17-L21).
- `DevicePublicIdentity { device_public_key, device_fingerprint }` (L24-L27).
- `PairingProof` (L30-L38): binding of `pairing_id`, `server_nonce`, `browser_session_id`,
  `requested_user_id`, device key + signature — the browser-initiated challenge the desktop signs.
- `DeviceRequestProof` (L41-L48): per-request signed envelope (session_id, fingerprint, unix-timestamp
  string, hex nonce, `sha256:<body>` digest, signature) used for **every** relay call.

Key functions:
- `verify_device_request_proof()` (L50-L97): validates fixed-width hex (64-char pubkey, 32-char nonce,
  128-char sig), 10-digit ASCII timestamp, recomputes `sha256:{hex}` over the exact bytes received,
  derives `VerifyingKey`, checks the fingerprint matches the key, then verifies the framed payload
  (`device_request_payload`, L661-L689: domain tag `"VECTANT-LOCAL-SUPPORT-DEVICE-V1"` +
  method/path/session/fingerprint/timestamp/nonce/body-hash, each length-prefixed u64 BE). This makes
  relay traffic replay-proof and body-tamper-proof end to end.
- `DeviceIdentity::generate/from_private_key_hex/sign_pairing_challenge/sign_device_request[_at]`
  (L104-L210): signing keys generated from `OsRng`; nonce = 16 random alphanumerics hex-encoded;
  timestamp = unix seconds string.
- `DeviceIdentityStore` (L222-L302): `load_or_create`, `load` (rejects files >8 KiB; verifies stored
  public fields re-derive from private key else `PublicIdentityMismatch`; auto-migrates legacy
  plaintext), `persist`, `reset`.
- **DPAPI at rest** (Windows): `encode_stored_identity`/`decode_stored_identity` (L314-L398) wrap the
  JSON in `CryptProtectData`/`CryptUnprotectData` with `CRYPTPROTECT_UI_FORBIDDEN`, prefixing the file
  with magic `VECTANT-DPAPI-V1\0` (L13-L14). On load, absence of the prefix means legacy plaintext →
  decrypt-less passthrough with `migrate=true` → immediately rewritten encrypted. Non-Windows stores
  plaintext with `0o600` file mode (`write_private_identity_file`, L543-L575, sync_all after write).
- Fingerprint derivation: `pairing_fingerprint` (L619-L625) = first 12 hex chars of
  SHA-256(`"vectant-local-support-pairing:" || code`) formatted `xxxx-xxxx-xxxx`; `device_fingerprint`
  (L627-L633) = `sha256:` + first 16 hex chars of SHA-256(`"vectant-local-support-device:" || pk`).
- `PairingSession` (L425-L489): 12-char uppercase alphanumeric code, TTL, **max 5 attempts**
  (`RateLimited` L467-L469), single-use (`Consumed`), expiry (`Expired`), and
  `constant_time_eq` comparison of both code and fingerprint (L478-L482) — timing-safe verification.
- `verify_pairing_proof` (L502-L531): shape-check every field (`safe_pairing_field` printable-ASCII
  bounds, L533-L541), decode/derive key, fingerprint-must-match-key, verify framed payload
  (`pairing_challenge_payload`, L635-L659, domain tag `"vectant-local-support-pairing-proof-v1"`).
- Tests: body/path/session binding of request proofs (L691-L741); Windows-only migration test proving
  plaintext identities get DPAPI-rewritten and no `private_key_hex` remains readable (L743-L772).

## 5. Session & authorization

### `src/session.rs` (366 lines) — session guard, replay protection, token rotation

- `SessionState` (L10-L20): the *sanitized* projection (session/account/org/workspace IDs, device
  fingerprint, `paused`, protocol version, permission mode, fast-support seconds). Deliberately
  excludes the bearer token — tested by `session_state_omits_token_material`.
- `SessionGuard` (L35-L47): private 48-char alphanumeric token, optional previous-token + overlap
  deadline (rotation), expiry, paused flag, fast-support window, and `seen_request_ids: HashSet`
  for **replay protection**.
- Constructors: `new_bound` (L50), `new_bound_device` (L72, binds a real device fingerprint — used by
  desktop & test daemon), `new_paired` (L94, validates the cloud-provided `sess_*` ID shape via
  `safe_request_id`).
- `request_device_proof_for_context()` (L203-L231): SHA-256 chain over domain tag
  `"vectant-local-support-device-proof-v1"` + token + session + request context (capability, actor,
  expiry, protocol/policy versions) → the per-request proof the HTTP layer compares constant-time.
  This binds each local API call to the exact request envelope.
- Token rotation (L274-L279): `rotate_connection_token(overlap)` swaps in a fresh token while keeping
  the old one valid until `now+overlap` — renewal over the relay can't strand an in-flight loopback
  request. Both current and previous tokens compared with `constant_time_eq`.
- `validate()/validate_control()` (L281-L312): order matters — expiry → token (current or overlap
  window) → safe request-id shape → pause gate (`validate_control` allows control commands through a
  pause; data requests don't) → **replay set insert** (duplicate request_id ⇒ `SessionError::Replay`).
  Unsafe IDs are rejected *before* touching the replay set (tested).
- Pause/resume/disconnect (L314-L327): disconnect zeroes expiry, re-pauses, clears fast-support and
  the replay set.
- Fast Support (L329-L334): `set_fast_support(true)` sets a 30-minute window clamped to session
  expiry; reflected in `state().permission_mode` as "Fast Support" vs "Balanced mode".

### `src/approval.rs` (431 lines) — approval queue with local-secret gating

- `QueuedApproval` (L38-L45): request, local review response, status, and a **hashed**
  `local_approval_secret` (`#[serde(skip)]`, never serialized).
- `ApprovalQueue::queue_file_review()` (L57-L81): denied reviews pass straight through; anything else
  gets an `appr_<uuid>` id, generates a fresh 48-char local secret, stores only its salted hash
  (`hash_local_approval_secret`, L419-L424: SHA-256 over `"vectant-local-support-local-approval-secret:"`),
  and returns the public pending response built by `public_pending_response` (L352-L369) — which
  carries **`content: None`** plus the message "No file content was sent before approval."
- Approval paths all require the secret: `approve_with_secret[_at]` (L90-L111),
  `approve_with_secret_and_current_review` (L113-L124, adds TOCTOU revalidation), deny-with-secret
  (L271-L279). Secret comparison is `constant_time_eq` on hashes (L333-L349).
- `approve_at_inner` (L162-L212): enforces id-shape (`is_safe_approval_id`, L402-L409:
  `appr_` prefix, ≤64 chars, charset), required prior status, RFC3339 expiry not yet passed (expired ⇒
  content dropped to None), optional revalidation that the freshly-read file still hash-matches the
  queued review (`review_still_matches`, L371-L376), then emits `(FileReadResponse, ConsentReceipt)`
  with `scope: "once"`.
- `grant_for_local_release()` (L226-L245): the desktop's native approve button marks a pending item
  approved locally; actual content release happens later through `release_granted_at`.
- `deny()` nulls content immediately (L214-L224); `revoke_all()` flips Pending/Approved → Revoked and
  drops all content (L281-L291); `pending_review_summaries()` (L247-L269) is the redacted-preview-only
  view for UI listing.
- `denied_approval_response()` (L378-L400): uniform denial with classification L5 and "Nothing was
  sent." messaging.

## 6. Workspace enforcement

### `src/workspace.rs` (741 lines) — path containment, capability graph, review pipeline

The heart of the read path.

Path containment:
- `resolve_relative()` (L510-L535): rejects NUL bytes; rejects Windows device/UNC prefixes via
  `has_forbidden_path_prefix` (L537-L548: `\\`, `\??\`, `\\.\`, `\\?\`, named pipes,
  drive letters); rejects absolute paths; allows only `Component::Normal` segments (kills `..`
  traversal); joins under root then **canonicalizes and re-checks containment** (`is_within`,
  L550-L558, case-insensitive prefix check on Windows).
- `is_sensitive_path()` (L560-L643): ~80-entry blocklist — credential dirs (`.ssh/.aws/.gcp/.azure/
  .kube/.docker`), VCS internals, dependency/vendor/build dirs, lockfiles, `.env*`, key/cert extensions,
  `id_rsa`-style keys, name-substrings `secret|credential|password|passwd|api_key`, minified/maps,
  sqlite/db/dump/sql/p12/pfx.
- `is_archive_path()` (L645-L650): zip/tar/tgz/gz/7z/rar/bz2/xz blocked outright.
- Sparse-file detection (`is_sparse_metadata`, L673-L689): unix blocks-vs-size heuristic; Windows
  `FILE_ATTRIBUTE_SPARSE_FILE`. Blocks decompression-bomb style logical-size lies.
- `safe_read_text()` (L465-L501): triple identity check (metadata-before-open vs after-open vs after-
  read via `same_file_identity` dev/ino on unix; size/creation/write-times/attrs on Windows L652-L671),
  size cap ≤ 256 KiB (`MAX_FILE_BYTES`, L16), sparse checks at every stage, NUL-byte binary rejection,
  UTF-8 validation, returns content + `sha256:` digest.

Capability graph (Full Access substrate):
- `build_capability_graph()` (L204-L295): recursive walk (cap `MAX_GRAPH_NODES = 20_000` from
  full_access), symlink-skipping, canonicalize-and-containment-check per entry; sensitive/archive/
  oversized/sparse files become `RiskClass::E` / `GraphNodeState::Blocked` nodes whose
  `relative_path` is replaced with the literal `"blocked_sensitive_category"` — raw sensitive paths
  never enter the graph (asserted by `capability_graph_has_no_raw_secret_paths_or_bodies`).
  Clean readable secret-free files get `RiskClass::B` / `AutoRequestable` + content hash. Node ids are
  `node_` + 16 hex of SHA-256(workspace_id ‖ display).
- `read_graph_node()` (L299-L309): reads **by node object**, never by caller-supplied path; refuses
  Blocked/E-class nodes and unsafe relative paths.
- `materialize_command_projection()` (L140-L199): builds a disposable temp dir
  (`vectant-command-<uuid>`, 0o700 on unix), copies only Available/AutoRequestable non-E nodes,
  re-validating content hash at copy time (`graph node changed` ⇒ abort) under a global 16 MiB cap;
  `Drop for CommandWorkspaceProjection` (L81-L85) removes the whole tree. Brokered commands therefore
  run against a sanitized snapshot, not the live workspace (test:
  `command_projection_excludes_sensitive_files_and_cannot_change_workspace`).

Review pipeline:
- `decide_file()` (L311-L340): workspace-id match, capability allowlist
  (`workspace.file.source.read` | `workspace.log.read`), actor allowlist (`vectant_ai` |
  `support_agent`), sensitive-path deny (L4), archive deny (L4), path resolution deny (L5) — otherwise
  `ApprovalRequired` with scrubbed display path.
- `read_file_for_review()` (L342-L429): policy first, then `safe_read_text`; scanner-unavailable ⇒
  hard deny ("Nothing was sent."); findings present ⇒ decision `redact_then_approval` with redacted
  content and redacted-content hash; clean ⇒ `approval_required` with original content held locally.
  All failures return structured `FileReadResponse`s with `bytes_sent: 0`.
- `scrub_display()` (L460-L463) runs scanner-redact over every user-visible path string.
- `WorkspaceSummary::summary()` (L115-L134): exposes folder display name + `root_hash` =
  SHA-256(`"vectant-local-support-workspace-root:" ‖ root`) with `root_path_included: false` — status
  surfaces prove workspace identity without leaking the absolute path
  (`workspace_status_summary_omits_raw_root_path`).

## 7. Full Access mode

## 8. Shell-free command broker

### `src/command_broker.rs` (876 lines)

Module doc: *"Bounded, shell-free command execution for Full Access diagnostics."*

- `CommandRequest { request_id, executable, arguments, timeout_seconds, max_output_bytes }`
  (L21-L28) → `CommandContext` (L30-L42): executable name, **hashed** arguments
  (`hash_arguments`, L524-L533: SHA-256 over `"vectant-command-arguments-v1\0"` + each arg), exit
  code, redaction count, captured stdout/stderr.
- `validate_request()` (L271-L300): absolute workspace, safe request id, `safe_executable` (bare
  name ≤80 chars, no separators), ≤64 args, timeout/output within policy — and membership in the
  policy executable allowlist, with a hard `shell_executable` deny-list (L445-L461: cmd, powershell,
  pwsh, sh, bash, zsh, fish, wscript, cscript — **denied even if an allowlist wrongly includes them**,
  tested by `shells_stay_denied_even_if_an_incorrect_policy_allowlists_them`).
- `dangerous_argument()` (L415-L443): rejects shell metacharacters (`| & ; > < \` $ newline`),
  interactive/eval-style flags (`-i`, `-c`, `-e`, `-m`, `--eval`, `--require`, …), embedded URLs, and
  any external/parent path shape (leading `/`, `\\`, `~`, drive letters, `=…`, `../`).

  (`safe_identifier`, base32-ish 12-char code alphabet without ambiguous chars L500-L503,
  `xxxx-xxxx-xxxx` fingerprint, future RFC3339 expiry). The pairing `code` is
  `#[serde(skip_serializing)]` on ClaimedPairing so it can't leak back out (asserted in tests).
- `complete()` posts the signed proof; `parse_completed_pairing` (L472-L489) enforces `sess_`
  prefix + fingerprint shape + future expiry before the desktop will trust it.
- `DesktopPolicyStatus` (L35-L107): availability/enabled/emergency controls
  (pairing_disabled / preview_gateway_disabled / agent_access_disabled — all defaulting **true** =
  denied when absent), version floor + vulnerable list, retention days (≤90 enforced), seven Full
  Access flags. `unavailable()` is fully deny-everything. Helpers `pairing_allowed`,
  `preview_allowed`, `full_access_allowed`, `update_version_allowed` all require
  available && enabled first.
- `parse_policy_status` (L248-L357): strict field validation, fail-closed defaults, user-visible
  message sanitized (≤240 chars, no newlines) with safe default strings.
- Extensive tests including real-loopback HTTP fetches and oversized-response rejection.

### `desktop/src/relay_client.rs` (737 lines)

- Same URL hardening pattern as pairing client but additionally pins the exact path
  `/api/local-support/relay/device` (L100-L109). Payload endpoint derived per-call.
- `post_signed()` (L352-L403): every request body signed by the device identity
  (`sign_device_request`) and sent with six `X-Vectant-*` headers (session id, fingerprint,
  timestamp, nonce, body sha256, signature) — server-side verification via `verify_device_request_proof`.
  Responses bounded at 64 KiB; HTTP 401/403 mapped to the sentinel `relay_session_denied`.
- `poll()` maps decisions to `RelayPoll::{Idle, Control, Delivery, Revoked}` with envelope
  validation: `RelayDelivery::validate` (L406-L446) and `RelayControlCommand::validate`
  (L448-L503) — identifier shapes, sha256 fingerprint length, lease-id hex, expiry parse, and an
  exact action allowlist (13 actions incl. full_access_enrollment_proposal,
  linked_project_activate/disconnect). Proposals ≤16 KiB and recursively rejected if any key contains
  token/secret/credential/private_key (`control_proposal_is_sensitive`, L505-L518).
- Upload paths cap sizes (status ≤12 KiB, linked-project ≤48 KiB, payload ≤384 KiB) and verify echo
  decisions + byte counts; `deny_reviewed_request` requires `bytes_sent == 0` in the ack.
- Tests exercise signature verification against a real socket (server re-verifies proofs), denial-as-
  revocation semantics, envelope validation, and transient-failure recovery.

### `desktop/src/bin/local_support_live_relay.rs` (159 lines)

Feature-gated staging probe reusing the production RelayClient + device-proof code (`#[path]`
include). Subcommands: identity / poll / outcome / control-outcome / upload; prints JSON results.
Explicitly excluded from the production desktop package.

## 16. Static UI & scripts

### `desktop/ui/index.html` (308 lines) / `desktop/ui/app.js` (762 lines) / `desktop/ui/styles.css`

Static, framework-free renderer (frontendDist `./ui`). Tabs: control plane, bootstrap, approvals,
ports, full access, activity. `app.js` reaches the daemon exclusively through
`window.__TAURI__...invoke("local_support_ipc", {command, payload})` (L585-L588) — no direct network
access is possible given the CSP. Buttons map 1:1 onto the IPC allowlist (workspace pick, pair,
approve/deny, port review/open/revoke, pause/resume/disconnect, revoke-all, full access
pause/enroll, process visibility, history, updates), each with user-visible failure text that never
includes sensitive detail.

### `scripts/windows-installer-smoke.ps1` (81 lines)

Installs the NSIS bundle silently into a GUID temp dir (path-escape guarded), launches the app
hidden, polls for a **127.0.0.1-bound listening socket owned by the app process** within 15 s
(proving loopback-only bind), then exercises the uninstaller.

### `target-windows-validation/` — live validation fixtures (not shipped code)

- `run-daemon.cmd`: starts the test daemon against a fixture project with ready-file env.
- `open-tunnel.cmd`: plink SSH loopback-port forward used by remote validation. ⚠️ Contains a
  hardcoded SSH hostkey **and password** in plaintext — a live-validation convenience credential that
  should not be treated as production secret material but is worth flagging in any security review.
- `run-process-probe.cmd`: launches the workspace probe exe pinned inside the fixture workspace.
- `validate_full_access.py` (147 lines): end-to-end Full Access exercise over HTTP — builds headers
  (origin/CSRF/bearer/versions), signs nothing itself (uses the daemon's printed token), walks enroll
  → graph → node → mutation → command → ports → processes flows asserting decisions.
