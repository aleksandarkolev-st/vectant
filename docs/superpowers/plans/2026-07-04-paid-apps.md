# Paid Apps — Implementation Plan

- **Date:** 2026-07-04
- **Spec:** [2026-07-04-paid-apps-design.md](../specs/2026-07-04-paid-apps-design.md)
- **Branch:** `feat/docker-sysbox-engine`
- **Method:** strict TDD, one commit per slice, surgical changes. `canPublish` untouched; paywall rides a new `canInstall`. Fail-closed everywhere. No live payments dependency in tests (inject prisma + fetch).

## Slices

### PB1 — Schema
- Add `ProgramPricing`, `Entitlement`, `PaymentWebhookEvent`; back-relations on `MarketplaceProgram`.
- `prisma generate`; `prisma db push` deferred if the local DB is down (commit schema + generate, note the follow-up — same as prior cycles).
- **Verify:** `prisma validate`; generated client has the new models.

### PB2 — Pricing store + validation (pure)
- `pricing.js`: `parsePricingInput({priceCents, currency, payoutAccountRef})` (non-negative int cents, known currency, take-rate from `PROGRAM_PLATFORM_TAKE_BPS`), `upsertPricing`, `getPricing`, `isPaid(program)`.
- **Tests:** valid/invalid cents, unknown currency, free vs paid detection.

### PB3 — Entitlement store + `canInstall` (pure)
- `paidEntitlements.js`: `hasActiveEntitlement({programId, subjectId})`, `grantEntitlement`, `revokeEntitlement` (idempotent).
- Extend `entitlements.js`: `canInstall({ userId, program, pricing, entitlement })` truth table — free → allow; paid → allow iff active entitlement; paid + billing env unset → deny (fail-closed).
- **Tests:** truth table (free/paid × entitled/not/revoked/config-missing); grant/revoke idempotency.

### PB4 — Checkout hand-off + HMAC reference
- `checkoutReference.js`: `signReference({programId, subjectId, priceCents})` / `verifyReference` (HMAC via `PAYMENTS_HANDOFF_SECRET`).
- `POST /workspace/:slug/programs/:packageId/checkout`: already-entitled → `{entitled:true}`; else return `{checkoutUrl}` with signed params (price server-authoritative).
- **Tests:** reference round-trip + tamper rejection; checkout returns entitled-noop vs checkout url; price taken from pricing, not client.

### PB5 — Webhook receiver (signed, idempotent)
- `POST /api/internal/payments/webhook`: verify `PAYMENTS_WEBHOOK_SECRET` signature (fail-closed 401); dedupe `eventId` via `PaymentWebhookEvent`; `purchase` → grant, `refund` → revoke.
- **Tests:** bad signature → 401 no-write; replay (same eventId) → single grant; purchase then refund → revoked; unknown reference handled.

### PB6 — Enforce paywall at install + launch
- `install/route.js`: load pricing+entitlement, call `canInstall`; miss → `402` `{priceCents, currency, checkoutUrl}`.
- `[installId]/launch/route.js` + MCP launch: re-check entitlement (refund/revoke blocks next launch).
- **Tests:** free installs; paid-unentitled → 402; paid-entitled → installs; revoked entitlement → launch blocked.

### PB7 — Redaction + serialization
- Extend the public/member program serializer: expose `priceCents`, `currency`, `entitled`, `isPaid`; **never** `payoutAccountRef`, `takeRateBps`, webhook payloads.
- **Tests:** serialized paid program hides payout ref + take-rate; buyer sees price + entitled.

### PB8 — Frontend
- Store card: price badge + **Buy** (→ checkout hand-off) / **Owned** state / **Install** for free.
- Publish/My-Apps: owner **Set price** control (cents, currency, payout ref) writing to the pricing route.
- **Tests:** raw react-dom/act component tests (existing convention) for price display, buy vs owned vs install, owner price setter.

### PB9 — Publisher earnings read-model + env docs
- `earnings.js`: derive gross/net (× take-rate) from entitlements for a publisher's apps (read-only; money movement is external).
- `.env.example`: `PAYMENTS_WEBHOOK_SECRET`, `PAYMENTS_HANDOFF_SECRET`, `PAYMENTS_CHECKOUT_URL`, `PROGRAM_PLATFORM_TAKE_BPS`.
- **Tests:** earnings math (gross, platform cut, net) per publisher.

### PB10 — Full verification
- Full JS suite green; `prisma validate`; `node --check`; document the deferred `db push` if it didn't run.

## Open items to confirm with the payments-app owner (not blocking PB1–PB3)

- The checkout URL contract (query vs POST; return/callback URL).
- The `payoutAccountRef` format + how a publisher onboards a payout account (likely a link into the payments app).
