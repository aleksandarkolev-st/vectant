The issue was a race condition in `backend/synthi-webrtc-compiler/worker/src/main.rs`.

The `x11_input_store` (which maps session IDs to X11 input channels) was being populated *after* the GStreamer pipeline was started and the success message was sent to the client.
If the client started sending GUI events (mouse/keyboard) immediately after receiving the "pipeline started" message, the worker would receive them before the input channel was registered, resulting in the "[worker] no x11 sender for session" error.

I moved the creation of the X11 input channel and its registration in `x11_input_store` to be earlier in the `handle_compile` function, specifically before the GStreamer pipeline creation loop. This ensures that the server is ready to handle input events by the time the client receives the success message.

Changes made:
- Moved `let (x11_tx, mut x11_rx) = mpsc::unbounded_channel::<String>();` and the `x11_input_store.insert` logic to lines ~1912, before the pipeline loop.
- Removed the duplicate logic from lines ~2150.
